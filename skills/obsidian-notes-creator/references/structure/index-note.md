# Index Notes

An index helps the reader choose where to start and where to go next. Update the existing index instead of creating a competing guide.

Include a short scope statement, meaningful groups of links, and prerequisites where needed. Add a concept map only when relationships are clearer visually than in the link list. A glossary or summary should not duplicate the detailed notes.

```markdown
# Subject

What this collection covers and what the reader should be able to do.

## Start here

- [[Subject/Foundations|Foundations]] — notation and assumptions used throughout.

## Methods

- [[Subject/Method A|Method A]] — when to use it and its worked example.
```

The paths are illustrative: replace them with existing, resolvable notes. Finish the index after the content is known; a planning skeleton may be useful earlier for a new collection. Do not mark topics complete just because their files exist. Preserve established date conventions.
