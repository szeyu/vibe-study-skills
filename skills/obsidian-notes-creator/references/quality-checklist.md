# Quality Checklist

Apply relevant checks to the requested scope. A checklist is a review aid, not a reason to add every possible section.

## Content

- [ ] The explanation answers the learner's likely question and fits the note's purpose.
- [ ] Definitions, assumptions, notation, units, and applicability are explicit where needed.
- [ ] Important reasoning steps are explained; exact and approximate results are distinguished.
- [ ] Worked examples contain sufficient givens, steps, results, interpretation, and an independent check.
- [ ] Relevant failure cases and diagnostic questions test understanding beyond recall.
- [ ] Analogies have accurate mappings and explicit limitations, if used.
- [ ] Empirical claims have sources and context; illustrative assumptions are labelled.

## Reader experience

- [ ] The intended reader and their prior knowledge were decided, and explanations build on that knowledge.
- [ ] The first lines say what the topic is and why it matters.
- [ ] Sentences are short, one idea each; every term is defined on first use; notation is read aloud in words.
- [ ] Concrete cases come before the general rule; tools are built by hand before the shortcut where it helps understanding.
- [ ] Each claim is followed closely by an example; no paragraph is purely abstract.
- [ ] Likely misconceptions and common mistakes are shown with fixes.
- [ ] Fine print sits in a later section instead of interrupting the main explanation.
- [ ] Notes of the same kind share the same shape; a folder has a guided reading path.
- [ ] Practice questions test reasoning (predict, spot the bug, change one thing), ordered easy to hard.
- [ ] No cramped bullets (label + explanation + code + link on one line); repeated sections share one layout; links come last.
- [ ] Every self-check uses the same question callout with a nested, unfolded Answer callout.
- [ ] A final read-through as the beginner found nothing they would have to scroll back for.

## Visuals and Obsidian

- [ ] Visuals have a specific teaching purpose and agree with the text and calculations.
- [ ] SVGs use white backgrounds by default, dark readable labels, accessible descriptions, and existing asset locations.
- [ ] Changed figures have been rendered and inspected at their intended display size, or that limitation is reported.
- [ ] Mathematics renders; symbols and domains were checked separately from syntax.
- [ ] Changed links, heading/block targets, and embeds resolve without ambiguity.
- [ ] Answers and solutions are visible unless hidden practice was explicitly requested.
- [ ] Existing layout, metadata, dates, and naming conventions are preserved appropriately.

## Completion

- [ ] Every in-scope note has a recorded review state; targeted work is labelled as targeted.
- [ ] Unchanged notes have a reason; cosmetic edits are not counted as substantive improvements.
- [ ] Calculation checks, runtime tests, syntax checks, and visual inspections are reported distinctly.
- [ ] Unresolved source gaps, unavailable tools, and remaining content issues are disclosed.

Follow [verification.md](verification.md) for the checking workflow. No mandatory diagram count, analogy count, or line count substitutes for these checks.
